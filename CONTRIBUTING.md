# Contributing

1. Open an issue describing the change.
2. Keep modules small and provider-independent.
3. Add tests for behavior changes.
4. Document permissions, data handling, costs, and failure modes.
5. Never commit secrets, tokens, customer data, or private business information.
6. Keep spending, publishing, and customer commitments behind explicit approval controls.

Pull requests should state what changed, how it was tested, and what remains incomplete.
